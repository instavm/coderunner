# Threat model

This covers the sandbox on `main`: `server.py` running in an Apple `container` VM on macOS (or a Docker
container, see [DOCKER_SETUP.md](DOCKER_SETUP.md)), the installer, and the MCP and REST clients that call it.
[AUTHENTICATION.md](AUTHENTICATION.md) has the details of the credential. Report vulnerabilities as described in
[SECURITY.md](SECURITY.md).

## What the sandbox is for

An agent (Claude Code, Claude Desktop, an SDK script) writes code and runs it in the sandbox instead of on the
host. The sandbox should keep that code away from the host's files, processes and credentials, except for the
directories the owner mounted. It does not make the code safe to run; it limits what the code can reach.

## Parties and trust

| Party | Trusted? | Notes |
| --- | --- | --- |
| Owner and their agent client on the host | Yes | Holds the API token, so it can run anything in the guest. |
| Code sent for execution | No | Written by a model that may have read hostile input. |
| Web pages opened by the browser tool | No | |
| Skills in `~/.coderunner/assets/skills/user` and uploaded skill archives | No | Their files are read by agents and may contain instructions. |
| Everything inside the guest | One level | Named Python sessions, the browser, Jupyter and the server share a filesystem, network and root user. |
| Other users and devices on the LAN, websites open in the owner's browser | No | Must not be able to call the API. |
| Base images and pinned dependencies | Yes, if they match their pins | |

## Boundaries

1. **Host ↔ guest.** With Apple `container` each container is a lightweight VM with its own kernel. With Docker
   the guest shares the host's kernel, which is a weaker boundary.
2. **Host filesystem.** The guest sees `skills/user` and `outputs` under `~/.coderunner/assets`, read-write, and
   any `--mount` the owner adds under `/workspace`, read-only unless `:rw`.
3. **API.** Port 8222. Every route except `GET/HEAD /health` needs the bearer token; Host and Origin headers must
   name the sandbox. In Apple `container`'s default network the guest has an address on the host's private
   VM network (`coderunner.local`); Docker Compose and the `none` network mode publish it on `127.0.0.1` only.
4. **Network out of the guest.** Unrestricted by default. `--network none` puts the guest on a host-only network
   with no route to the internet or the LAN.

## Threats

| # | Threat | Mitigation | What remains |
| --- | --- | --- | --- |
| 1 | Another device on the LAN, or another local user, calls the API and runs code. | Bearer token of 32+ bytes, compared in constant time, generated by the installer into `~/.coderunner/api-token` (mode 0600). Docker publishes on loopback only. | HTTP is not encrypted. Any process running as the owner can read the token file. |
| 2 | A website open in the owner's browser posts to `coderunner.local:8222` (CSRF, DNS rebinding). | The browser has no token. Host and Origin must be one of the sandbox's own names. | None known. |
| 3 | Code escapes the guest to the host. | VM isolation with Apple `container`. | Hypervisor or VM bugs. Under Docker, a kernel exploit reaches the host. The guest runs as root. |
| 4 | Code reads or changes host files. | Only the directories listed above are mounted. Extra mounts are read-only unless `:rw`. | Anything mounted read-write can be changed or deleted. A file written to `skills/user` persists and is later read by agents as a skill. |
| 5 | Code sends data out (mounted files, outputs, anything it fetched). | `--network none`. | In the default mode there is no egress filter. There is no allowlist mode on `main`. |
| 6 | Code attacks the LAN or the host's services (router admin pages, other machines, services on the host). | `--network none`. | In the default mode the guest can reach the LAN and the host like any other machine on it. |
| 7 | The browser tool is pointed at an internal address, directly or through a redirect, frame or subresource (SSRF), to reach Jupyter, the host gateway or the LAN. | Only public `http(s)` addresses. Every request the page makes goes through a route that checks its resolved addresses with `is_global`, which also refuses `100.64.0.0/10`. 30 s timeout, page text capped at 200,000 characters. | Chromium resolves the name again when it connects, so a name that changes address between the check and the connection is not caught. Page routes do not see WebSocket traffic, service workers or the first request of a popup. Code in the guest can reach the same addresses directly; this guard matters when only the browser tool is exposed. |
| 8 | A skill archive writes outside its directory or exhausts the disk. | Paths resolved and checked before extraction, only regular files and directories accepted, symlinks refused, 200 MB unpacked limit. A bad archive is set aside. | None known. |
| 9 | Code with side effects runs twice after a transport error. | Named sessions never retry. The unnamed path retries only failures that happened before the code was sent; a failure after sending counts as sent. | Clients that retry on their own can still run code twice. |
| 10 | Code in the guest reads the token. | None. The server needs it, and code in the guest can read the server's environment. | The token gives nothing the guest does not already have, but it must not be reused for anything else. |
| 11 | One agent's session reads or changes another's state. | Named sessions have separate interpreters. | Sessions share the guest. They are not a security boundary between agents that do not trust each other. |
| 12 | A compromised dependency or image. | Base images pinned to digests, Python packages installed with `--require-hashes`, Actions pinned to commit SHAs, Dependabot. The installer refuses images that ignore the token. | Published images are not signed and the installer does not verify provenance. |

## Out of scope

- Malware already running as the owner on the host. It can read the token and the mounted directories directly.
- A compromised or malicious agent client. It holds the token by design.
- Prompt injection that leads the agent to send harmful code. The sandbox limits where that code can reach; it
  does not judge the code.
- Several users with different permissions. The token is one credential with full access.

## Planned

- Sign published images and verify signature and provenance in the installer (item 12).
- An egress mode that allows package registries and asks the owner before other hosts (items 5 and 6).
- An end-to-end install test in CI. Apple `container` cannot run on GitHub's hosted macOS runners, so Docker is
  tested there and the Apple path on a Mac before each release.
